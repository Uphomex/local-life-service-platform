## 一、项目重点

### 1.1 安全认证

**重点内容：**

1. **JWT Token生成与验证**
   - 使用HS256算法签名
   - Token包含用户ID、角色、过期时间
   - 验证时检查签名和过期时间

2. **密码加密**
   - 使用BCryptPasswordEncoder
   - 不可逆加密，防止密码泄露

3. **角色权限控制**
   - Spring Security配置角色访问规则
   - 使用`@PreAuthorize`注解细粒度控制

**关键代码位置：**
- `security/JwtTokenProvider.java` - Token生成和验证
- `security/JwtAuthenticationFilter.java` - 请求拦截
- `config/SecurityConfig.java` - 权限配置

### 1.2 订单状态机

**重点内容：**

1. **状态流转规则**
   - PENDING → PAID → DELIVERING → COMPLETED
   - 任何状态都可转换为CANCELLED

2. **状态转换验证**
   - 不能从COMPLETED转换为DELIVERING
   - 不能从CANCELLED转换为其他状态

3. **状态变更通知**
   - 通过Kafka发送状态变更消息
   - 前端订阅消息更新UI

**关键代码位置：**
- `service/impl/OrderServiceImpl.java` - 状态转换逻辑
- `entity/Order.java` - 状态字段定义

### 1.3 库存管理

**重点内容：**

1. **库存锁定机制**
   - 使用Redis分布式锁
   - 防止超卖

2. **库存扣减流程**
   - 创建订单时锁定库存
   - 支付成功后扣减库存
   - 订单取消时释放库存

3. **库存缓存**
   - Redis缓存库存数量
   - 定时同步到数据库

**关键代码位置：**
- `service/impl/ProductServiceImpl.java` - 库存操作
- `service/impl/OrderServiceImpl.java` - 订单创建时扣减库存

### 1.4 骑手调度

**重点内容：**

1. **骑手位置跟踪**
   - 实时更新骑手位置
   - 使用Redis存储位置信息

2. **订单分配算法**
   - 优先分配给附近骑手
   - 考虑骑手负载

3. **配送状态更新**
   - 骑手更新配送进度
   - 实时通知用户

**关键代码位置：**
- `service/impl/RiderServiceImpl.java` - 骑手操作
- `controller/RiderController.java` - 骑手接口

### 1.5 缓存策略

**重点内容：**

1. **热点数据缓存**
   - 商家信息、商品信息
   - 减少数据库查询

2. **缓存更新策略**
   - 写操作时更新缓存
   - 设置合理的过期时间

3. **缓存穿透处理**
   - 空值缓存
   - 布隆过滤器

**关键代码位置：**
- `config/RedisConfig.java` - Redis配置
- `service/impl/ProductServiceImpl.java` - 库存缓存

### 1.6 异步消息

**重点内容：**

1. **消息队列使用场景**
   - 订单创建通知
   - 订单状态变更
   - 骑手分配通知

2. **消息可靠性**
   - 消息持久化
   - 消费者确认机制

3. **消息解耦**
   - 订单服务不依赖通知服务
   - 异步处理提升性能

**关键代码位置：**
- `service/impl/OrderServiceImpl.java` - 发送消息
- `service/impl/RiderServiceImpl.java` - 接收消息

## 二、常见易错点

### 2.1 数据库连接配置

**常见错误：**

1. **连接URL错误**
   - 端口号错误（默认3306）
   - 数据库名称错误
   - 时区配置缺失

2. **用户名密码错误**
   - 大小写敏感
   - 特殊字符转义

3. **驱动类配置**
   - MySQL 8.0使用`com.mysql.cj.jdbc.Driver`
   - 旧版本使用`com.mysql.jdbc.Driver`

**正确配置示例：**

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/local_life_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
    username: admin
    password: password
    driver-class-name: com.mysql.cj.jdbc.Driver
```

### 2.2 Redis缓存一致性

**常见错误：**

1. **缓存与数据库不一致**
   - 更新数据库后忘记更新缓存
   - 缓存过期时间设置不当

2. **缓存穿透**
   - 查询不存在的数据
   - 每次都访问数据库

3. **缓存雪崩**
   - 大量缓存同时过期
   - 导致数据库压力过大

**解决方案：**

```java
// 更新数据时同时更新缓存
public void updateProduct(Long id, ProductCreateRequest request) {
    Product product = productMapper.selectById(id);
    product.setName(request.getName());
    productMapper.updateById(product);
    
    // 更新缓存
    redisTemplate.opsForValue().set("product:" + id, product);
}
```

### 2.3 JWT令牌验证

**常见错误：**

1. **Token过期处理**
   - 未处理Token过期异常
   - 用户体验差

2. **Token解析失败**
   - Secret密钥不一致
   - Token格式错误

3. **Token存储不安全**
   - 存储在localStorage可能被XSS攻击获取
   - 建议使用HttpOnly Cookie

**正确做法：**

```java
public boolean validateToken(String token) {
    try {
        Jwts.parser()
                .verifyWith(getSigningKey())
                .build()
                .parseSignedClaims(token);
        return true;
    } catch (ExpiredJwtException e) {
        log.warn("Token expired");
        return false;
    } catch (JwtException | IllegalArgumentException e) {
        log.warn("Invalid token");
        return false;
    }
}
```

### 2.4 事务管理

**常见错误：**

1. **事务未生效**
   - 方法不是public
   - 内部调用不触发事务

2. **事务回滚失败**
   - 捕获异常后未重新抛出
   - 使用了非检查异常

3. **事务传播配置错误**
   - 默认传播行为不适合所有场景
   - 需要根据业务配置

**正确配置：**

```java
@Service
public class OrderServiceImpl {
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public OrderResponse createOrder(Long userId, OrderCreateRequest request) {
        // 业务逻辑
        if (errorCondition) {
            throw new ServiceException("订单创建失败");
        }
    }
}
```

### 2.5 跨域问题

**常见错误：**

1. **CORS配置不全**
   - 未配置`allowedOriginPatterns`
   - 未配置`allowCredentials`

2. **预检请求失败**
   - OPTIONS请求被拦截
   - 需要配置允许OPTIONS方法

**正确配置：**

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}
```

### 2.6 Kafka消息丢失

**常见错误：**

1. **生产者消息丢失**
   - 未配置消息确认
   - 网络问题导致消息未发送

2. **消费者消息丢失**
   - 自动提交偏移量
   - 处理失败但偏移量已提交

3. **消息重复消费**
   - 消费者重启导致重复处理
   - 需要实现幂等性

**正确配置：**

```yaml
spring:
  kafka:
    producer:
      retries: 3
      acks: all
    consumer:
      enable-auto-commit: false
      auto-offset-reset: earliest
```

## 三、技术选型理由

### 3.1 为什么选择Spring Boot

**理由：**

1. **社区成熟**：Spring Boot是Java生态中最成熟的Web框架之一
2. **自动配置**：减少大量样板代码，快速启动
3. **生态完善**：与Spring Security、Spring Data、Spring Cloud无缝集成
4. **便于扩展**：单体应用可以轻松迁移到微服务架构
5. **文档丰富**：大量教程和社区支持

### 3.2 为什么选择MyBatis Plus

**理由：**

1. **简化CRUD**：继承BaseMapper即可获得基础CRUD操作
2. **Lambda表达式**：类型安全的查询条件构建
3. **分页支持**：内置分页插件
4. **代码生成**：自动生成Mapper、Service、Controller
5. **灵活SQL**：支持XML和注解两种方式

### 3.3 为什么选择JWT

**理由：**

1. **无状态认证**：服务器不需要保存会话，便于水平扩展
2. **跨域支持**：Token可以在不同域之间传递
3. **安全性**：签名机制保证Token不被篡改
4. **灵活性**：可以携带自定义信息

### 3.4 为什么选择Redis

**理由：**

1. **高性能缓存**：内存数据库，读写速度快
2. **数据结构丰富**：支持String、Hash、List、Set、Sorted Set
3. **分布式锁**：支持原子操作，实现分布式锁
4. **地理位置支持**：支持Geospatial操作，适合骑手位置管理
5. **发布订阅**：支持消息发布订阅模式

### 3.5 为什么选择Kafka

**理由：**

1. **高吞吐量**：每秒处理百万级消息
2. **消息持久化**：消息写入磁盘，不会丢失
3. **分布式架构**：支持水平扩展
4. **消息分区**：提高并发处理能力
5. **消费者组**：支持多个消费者并行处理

### 3.6 为什么选择Vue 3

**理由：**

1. **响应式系统**：Composition API更灵活
2. **性能优化**：响应式系统重写，性能更好
3. **TypeScript支持**：更好的类型推断
4. **组件化开发**：代码复用性好
5. **生态完善**：Element Plus等成熟组件库

## 四、性能优化建议

### 4.1 数据库优化

1. **索引优化**
   - 为查询字段创建索引
   - 避免全表扫描

2. **分库分表**
   - 订单表按时间分表
   - 商家表按区域分库

3. **查询优化**
   - 使用JOIN减少查询次数
   - 避免SELECT *

### 4.2 缓存优化

1. **多级缓存**
   - 本地缓存（Caffeine）
   - 分布式缓存（Redis）

2. **缓存预热**
   - 启动时加载热点数据
   - 定时更新缓存

3. **缓存淘汰策略**
   - LRU/LFU策略
   - 根据业务调整

### 4.3 代码优化

1. **异步处理**
   - 使用CompletableFuture
   - 非核心逻辑异步执行

2. **批量操作**
   - 批量插入/更新
   - 减少数据库连接次数

3. **对象复用**
   - 使用对象池
   - 减少GC压力

## 📌 总结

### 重点关注：
1. **安全认证**：JWT + Spring Security
2. **订单流程**：状态机管理
3. **数据一致性**：缓存与数据库同步
4. **性能优化**：缓存、异步、批量操作

### 易错点规避：
1. 配置文件检查（数据库、Redis、Kafka）
2. 事务配置（rollbackFor、传播行为）
3. 异常处理（不要吞掉异常）
4. 缓存更新（写操作后更新缓存）

### 技术选型原则：
1. 成熟稳定优先
2. 社区活跃优先
3. 易于维护优先
4. 便于扩展优先
