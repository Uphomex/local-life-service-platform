|------|------|------|----------|
| 语言 | Java | 21 | LTS版本，性能稳定，生态成熟 |

| 安全 | Spring Security + JWT | - | 成熟的安全框架，无状态认证 |

### 1.3 架构特点

1. **单体应用架构**：所有功能集中在一个应用中，便于开发和部署
2. **分层架构**：清晰的职责划分，便于维护和扩展
3. **无状态设计**：使用JWT实现无状态认证，便于水平扩展
4. **缓存策略**：Redis缓存热点数据，提升性能
5. **异步处理**：Kafka处理异步任务，解耦系统
6. **模块化设计**：按业务域划分模块，便于后续微服务拆分

## 二、分层架构详解

### 2.1 Controller层

**职责：**
- 接收HTTP请求
- 参数校验
- 调用Service层
- 返回统一格式响应

**设计原则：**
- 不包含业务逻辑
- 使用DTO进行数据传输
- 处理HTTP状态码

**示例代码结构：**

```java
@RestController
@RequestMapping("/api/auth")
public class AuthController {
    private final UserService userService;
    
    @PostMapping("/login")
    public ResponseEntity<ResponseResult<LoginResponse>> login(
            @Valid @RequestBody LoginRequest request) {
        LoginResponse response = userService.login(request);
        return ResponseEntity.ok(ResponseResult.success(response));
    }
}
```

### 2.2 Service层

**职责：**
- 业务逻辑处理
- 事务管理
- 调用Repository层

**设计原则：**
- 接口与实现分离
- 使用@Transactional注解管理事务
- 抛出业务异常

**示例代码结构：**

```java
public interface UserService {
    LoginResponse login(LoginRequest request);
    void register(RegisterRequest request);
}

@Service
public class UserServiceImpl implements UserService {
    @Override
    @Transactional
    public LoginResponse login(LoginRequest request) {
        // 业务逻辑处理
    }
}
```

### 2.3 Repository层

**职责：**
- 数据访问
- SQL执行
- 结果映射

**设计原则：**
- 使用MyBatis Plus BaseMapper
- 自定义SQL使用@Select/@Insert等注解
- 避免在Mapper中写业务逻辑

**示例代码结构：**

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
    @Select("SELECT * FROM user WHERE username = #{username}")
    Optional<User> findByUsername(@Param("username") String username);
}
```

### 2.4 Entity层

**职责：**
- 数据库表映射
- 数据存储

**设计原则：**
- 使用Lombok注解简化代码
- 字段与数据库列对应
- 使用@TableName指定表名

**示例代码结构：**

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
@TableName("user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String username;
    private String password;
    // ...
}
```

### 2.5 DTO层

**职责：**
- 请求数据封装
- 响应数据封装
- 数据校验

**设计原则：**
- 请求DTO使用@Valid注解校验
- 响应DTO只返回必要字段
- 避免直接暴露Entity

**示例代码结构：**

```java
// 请求DTO
@Data
public class LoginRequest {
    @NotBlank(message = "用户名不能为空")
    private String username;
    @NotBlank(message = "密码不能为空")
    private String password;
}

// 响应DTO
@Data
public class LoginResponse {
    private Long userId;
    private String username;
    private String role;
    private String token;
}
```

## 三、核心业务流程

### 3.1 用户认证流程

```
用户登录
    │
    ▼
┌─────────────────┐
│ AuthController  │
│   /api/auth/login│
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ UserServiceImpl │
│    login()      │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
 查询用户   验证密码
    │         │
    └────┬────┘
         ▼
   生成JWT Token
         │
         ▼
    返回登录响应
```

**流程说明：**

1. 用户调用登录接口 `/api/auth/login`
2. Controller接收请求并校验参数
3. Service层查询用户并验证密码
4. 使用BCryptPasswordEncoder验证密码
5. 生成JWT Token（包含用户ID和角色）
6. 返回登录成功响应

## 四、数据模型设计

### 4.1 数据库表关系

```
user (用户表)
  │
  ├─→ merchant (商家表) [user.id = merchant.user_id]
  ├─→ rider (骑手表) [user.id = rider.user_id]
  └─→ review (评价表) [user.id = review.user_id]

merchant (商家表)
  │
  ├─→ product (商品表) [merchant.id = product.merchant_id]
  └─→ review (评价表) [merchant.id = review.merchant_id]

product (商品表)
  │
  ├─→ product_attribute (商品属性表) [product.id = product_attribute.product_id]
  ├─→ product_sku (商品SKU表) [product.id = product_sku.product_id]
  └─→ order_item (订单项表) [product.id = order_item.product_id]

order (订单表)
  │
  ├─→ order_item (订单项表) [order.id = order_item.order_id]
  ├─→ review (评价表) [order.id = review.order_id]
  └─→ rider (骑手表) [order.rider_id = rider.id]
```

### 4.2 核心实体关系

| 实体 | 说明 | 关联关系 |
|------|------|----------|
| User | 用户 | 一对多 Merchant, Rider, Review |
| Merchant | 商家 | 一对多 Product, Review |
| Product | 商品 | 一对多 ProductAttribute, ProductSku, OrderItem |
| Order | 订单 | 一对多 OrderItem, Review；多对一 Rider |
| Rider | 骑手 | 一对多 Order |
| Review | 评价 | 多对一 User, Merchant, Order, Product |

## 五、状态机设计

### 5.1 用户状态机

```
INACTIVE ──→ ACTIVE ──→ INACTIVE
    ↑                          │
    └──────────────────────────┘
```

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| INACTIVE | 未激活 | 用户注册后待激活 |
| ACTIVE | 活跃 | 用户激活或管理员审核通过 |

### 5.2 商家状态机

```
PENDING ──→ ACTIVE ──→ INACTIVE
    ↑                          │
    └──────────────────────────┘
```

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| PENDING | 待审核 | 商家注册提交 |
| ACTIVE | 营业中 | 管理员审核通过 |
| INACTIVE | 停业 | 商家申请或管理员操作 |

### 5.3 订单状态机

```
PENDING ──→ PAID ──→ DELIVERING ──→ COMPLETED
   │              │            │
   └──────────────┴────────────┘
           CANCELLED
```

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| PENDING | 待支付 | 创建订单 |
| PAID | 待接单 | 用户支付成功 |
| DELIVERING | 配送中 | 骑手接单 |
| COMPLETED | 已完成 | 用户确认收货 |
| CANCELLED | 已取消 | 用户取消或超时 |

### 5.4 骑手状态机

```
PENDING ──→ ACTIVE ──→ INACTIVE
    ↑                          │
    └──────────────────────────┘
```

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| PENDING | 待审核 | 骑手注册提交 |
| ACTIVE | 在线 | 审核通过，骑手上线 |
| INACTIVE | 离线 | 骑手下线或管理员操作 |

## 六、安全架构

### 6.1 JWT认证机制

**Token结构：**

```
Header.Payload.Signature

Header: {"alg": "HS256", "typ": "JWT"}
Payload: {"userId": 1, "role": "USER", "sub": "username", "exp": 1704067200}
Signature: HMACSHA256(base64Url(header) + "." + base64Url(payload), secret)
```

**认证流程：**

1. 用户登录成功后获取Token
2. 后续请求在Header中携带 `Authorization: Bearer <token>`
3. JwtAuthenticationFilter拦截请求并验证Token
4. 从Token中提取用户ID和角色
5. 设置Spring Security上下文

### 6.2 角色权限控制

**角色定义：**

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| ADMIN | 管理员 | 所有接口 |
| MERCHANT | 商家 | 商家相关接口 |
| RIDER | 骑手 | 骑手相关接口 |
| USER | 普通用户 | 用户相关接口 |

**权限配置：**

```java
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/auth/**", "/swagger-ui/**").permitAll()
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
    .requestMatchers("/api/merchant/**").hasRole("MERCHANT")
    .requestMatchers("/api/rider/**").hasRole("RIDER")
    .anyRequest().authenticated()
)
```

### 6.3 密码安全

**加密策略：**

- 使用BCryptPasswordEncoder加密密码
- 每次加密生成不同的salt
- 密码存储为哈希值，不可逆

**示例代码：**

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}

// 注册时加密
user.setPassword(passwordEncoder.encode(request.getPassword()));

// 登录时验证
passwordEncoder.matches(request.getPassword(), user.getPassword());
```

## 📌 总结

本项目采用**分层架构**设计，具有以下特点：

1. **清晰的职责划分**：Controller处理请求，Service处理业务，Repository处理数据
2. **安全的认证机制**：JWT无状态认证，BCrypt密码加密
3. **高效的数据处理**：Redis缓存热点数据，Kafka异步处理
4. **完善的业务流程**：订单状态机、商家入驻流程、骑手调度等
5. **便于扩展**：模块化设计，便于后续微服务改造
